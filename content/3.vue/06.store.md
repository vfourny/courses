## Pourquoi un store ?

Dans une application Vue, plusieurs composants peuvent avoir besoin des **mêmes données** : un composant d'en-tête qui affiche le nom de l'utilisateur connecté, une page profil qui affiche ses informations, un composant de navigation qui adapte ses liens selon l'authentification...

Gérer ces données uniquement via des props et des événements devient vite ingérable :

```
App.vue
├── Header.vue      ← a besoin de l'utilisateur connecté
├── Sidebar.vue     ← a besoin de l'utilisateur connecté
└── ProfilePage.vue ← a besoin de l'utilisateur connecté
```

Un **store** centralise ces données dans un état global partagé, accessible depuis n'importe quel composant sans "prop drilling".

## Pinia

**Pinia** est le store officiel de Vue 3. Il utilise la Composition API, ce qui le rend intuitif et cohérent avec l'écriture des composants.

### Installation

```sh
npm install pinia
```

```ts
// main.ts
import naive from 'naive-ui'
import { createPinia } from 'pinia'
import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)
app.use(createPinia()) // Enregistrer Pinia
app.use(naive)
app.mount('#app')
```

## Créer un store

Un store Pinia avec le **Setup Store** (style Composition API recommandé) ressemble à un composable, mais son état est **global et partagé** entre tous les composants.

### Exemple : store d'authentification

```ts
// src/store/auth.ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'
import { useStorage } from '@/composables/useStorage'

interface User {
  id: number
  email: string
  username: string
}

export const useAuthStore = defineStore('auth', () => {
  const storage = useStorage()

  // État
  const token = ref<string | null>(storage.get<string>('token'))
  const user = ref<User | null>(storage.get<User>('user'))

  // Getters (propriétés dérivées)
  const isAuthenticated = computed(() => !!token.value)

  // Actions
  const login = (newToken: string, newUser: User): void => {
    token.value = newToken
    user.value = newUser
    storage.set('token', newToken)
    storage.set('user', newUser)
  }

  const logout = (): void => {
    token.value = null
    user.value = null
    storage.remove('token', 'user')
  }

  return { token, user, isAuthenticated, login, logout }
})
```

### Structure d'un Setup Store

| Élément | Équivalent dans un composant | Rôle |
| --- | --- | --- |
| `ref()` / `reactive()` | `ref()` / `reactive()` | État du store |
| `computed()` | `computed()` | Valeurs dérivées (getters) |
| Fonctions | Méthodes | Actions (modifient l'état) |
| `return { ... }` | — | Expose ce qui est accessible |

## Utiliser un store dans un composant

```vue
<template>
  <div>
    <p v-if="isAuthenticated">Bonjour, {{ user?.username }}</p>
    <NButton v-else type="primary" @click="goToLogin">Se connecter</NButton>
    <NButton v-if="isAuthenticated" @click="handleLogout">Déconnexion</NButton>
  </div>
</template>

<script setup lang="ts">
import { useRouter } from 'vue-router'
import { useAuthStore } from '@/store/auth'
import { storeToRefs } from 'pinia'

const router = useRouter()
const authStore = useAuthStore()

// storeToRefs extrait les propriétés réactives tout en conservant la réactivité
const { user, isAuthenticated } = storeToRefs(authStore)

const handleLogout = () => {
  authStore.logout()
  router.push('/auth/login')
}

const goToLogin = () => {
  router.push('/auth/login')
}
</script>
```

> **Important :** Utilisez toujours `storeToRefs()` pour déstructurer les **propriétés réactives** (state et getters) du store. Pour les **actions**, déstructurez-les directement depuis le store (`const { logout } = authStore`).

## storeToRefs : pourquoi c'est nécessaire

```ts
// ❌ Mauvais : perd la réactivité
const { user, isAuthenticated } = authStore

// ✅ Correct : conserve la réactivité
const { user, isAuthenticated } = storeToRefs(authStore)

// ✅ Les actions se déstructurent directement (pas de réactivité à conserver)
const { login, logout } = authStore
```

## Exemple complet : store de compteur partagé

```ts
// src/store/counter.ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'

export const useCounterStore = defineStore('counter', () => {
  const count = ref<number>(0)
  const doubled = computed(() => count.value * 2)

  const increment = () => count.value++
  const reset = () => (count.value = 0)

  return { count, doubled, increment, reset }
})
```

Ce store est maintenant accessible depuis **n'importe quel composant** et son état est **partagé** : si `ComponentA` incrémente le compteur, `ComponentB` verra immédiatement la nouvelle valeur.

```vue
<!-- ComponentA.vue -->
<template>
  <button @click="counterStore.increment()">+</button>
</template>

<script setup lang="ts">
import { useCounterStore } from '@/store/counter'
const counterStore = useCounterStore()
</script>
```

```vue
<!-- ComponentB.vue -->
<template>
  <p>Valeur : {{ count }} (double : {{ doubled }})</p>
</template>

<script setup lang="ts">
import { storeToRefs } from 'pinia'
import { useCounterStore } from '@/store/counter'
const { count, doubled } = storeToRefs(useCounterStore())
</script>
```

## Persistance de l'état

Par défaut, l'état d'un store est **réinitialisé** si l'utilisateur rafraîchit la page. Pour persister des données (comme le token d'authentification), stockez-les dans le `localStorage` à chaque modification — comme montré dans l'exemple du store d'authentification avec `useStorage`.
