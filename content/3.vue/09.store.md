Dans ce chapitre, on continue de construire notre Movie Watchlist en ajoutant un état global partagé : `useAuthStore` pour l'authentification et `useWatchlistStore` pour les films sauvegardés.

## Pourquoi un store ?

Dans une application Vue, plusieurs composants peuvent avoir besoin des **mêmes données** : la navbar qui affiche le nombre de films dans la watchlist, la page watchlist qui liste les films, un bouton "Ajouter" sur la page de détail...

Gérer ces données uniquement via des props et des événements devient vite ingérable :

```
App.vue
├── NavMenu.vue         ← affiche "3 films dans ma watchlist"
├── WatchlistPage.vue   ← liste les films de la watchlist
└── MovieDetailPage.vue ← bouton "Ajouter à la watchlist"
```

Un **store** centralise ces données dans un état global partagé, accessible depuis n'importe quel composant sans "prop drilling".

## Pinia

**Pinia** est le store officiel de Vue 3. Il utilise la Composition API, ce qui le rend intuitif et cohérent avec l'écriture des composants.

### Installation

```sh
npm install pinia
```

```ts
// main.ts
import naive from 'naive-ui'
import { createPinia } from 'pinia'
import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)
app.use(createPinia()) // Enregistrer Pinia
app.use(naive)
app.mount('#app')
```

## Créer un store

Un store Pinia avec le **Setup Store** (style Composition API recommandé) ressemble à un composable, mais son état est **global et partagé** entre tous les composants.

### Exemple : store d'authentification

```ts
// src/store/auth.ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'
import { useStorage } from '@/composables/useStorage'

interface User {
  id: number
  email: string
  username: string
}

export const useAuthStore = defineStore('auth', () => {
  const storage = useStorage()

  // État
  const token = ref<string | null>(storage.get<string>('token'))
  const user = ref<User | null>(storage.get<User>('user'))

  // Getters (propriétés dérivées)
  const isAuthenticated = computed(() => !!token.value)

  // Actions
  const login = (newToken: string, newUser: User): void => {
    token.value = newToken
    user.value = newUser
    storage.set('token', newToken)
    storage.set('user', newUser)
  }

  const logout = (): void => {
    token.value = null
    user.value = null
    storage.remove('token', 'user')
  }

  return { token, user, isAuthenticated, login, logout }
})
```

### Structure d'un Setup Store

| Élément | Équivalent dans un composant | Rôle |
| --- | --- | --- |
| `ref()` / `reactive()` | `ref()` / `reactive()` | État du store |
| `computed()` | `computed()` | Valeurs dérivées (getters) |
| Fonctions | Méthodes | Actions (modifient l'état) |
| `return { ... }` | — | Expose ce qui est accessible |

## Utiliser un store dans un composant

```vue
<template>
  <div>
    <p v-if="isAuthenticated">Bonjour, {{ user?.username }}</p>
    <NButton v-else type="primary" @click="goToLogin">Se connecter</NButton>
    <NButton v-if="isAuthenticated" @click="handleLogout">Déconnexion</NButton>
  </div>
</template>

<script setup lang="ts">
import { useRouter } from 'vue-router'
import { useAuthStore } from '@/store/auth'
import { storeToRefs } from 'pinia'

const router = useRouter()
const authStore = useAuthStore()

// storeToRefs extrait les propriétés réactives tout en conservant la réactivité
const { user, isAuthenticated } = storeToRefs(authStore)

const handleLogout = () => {
  authStore.logout()
  router.push('/login')
}

const goToLogin = () => {
  router.push('/login')
}
</script>
```

> **Important :** Utilisez toujours `storeToRefs()` pour déstructurer les **propriétés réactives** (state et getters) du store. Pour les **actions**, déstructurez-les directement depuis le store (`const { logout } = authStore`).

## storeToRefs : pourquoi c'est nécessaire

```ts
// ❌ Mauvais : perd la réactivité
const { user, isAuthenticated } = authStore

// ✅ Correct : conserve la réactivité
const { user, isAuthenticated } = storeToRefs(authStore)

// ✅ Les actions se déstructurent directement (pas de réactivité à conserver)
const { login, logout } = authStore
```

## Exemple complet : store de watchlist partagé

Le compteur de films dans la navbar justifie un store global : ce nombre doit être le même dans tous les composants.

```ts
// src/store/watchlist.ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'
import { useLocalStorage } from '@/composables/useLocalStorage'

interface Movie {
  id: number
  title: string
  genre: string
  year: number
  seen: boolean
}

export const useWatchlistStore = defineStore('watchlist', () => {
  // Persisté automatiquement dans le localStorage
  const movies = useLocalStorage<Movie[]>('watchlist', [])

  const count = computed(() => movies.value.length)
  const seenCount = computed(() => movies.value.filter((m) => m.seen).length)

  const addMovie = (movie: Movie) => {
    if (!movies.value.find((m) => m.id === movie.id)) {
      movies.value.push(movie)
    }
  }

  const removeMovie = (id: number) => {
    movies.value = movies.value.filter((m) => m.id !== id)
  }

  return { movies, count, seenCount, addMovie, removeMovie }
})
```

Ce store est maintenant accessible depuis **n'importe quel composant** et son état est **partagé** : si `MovieDetailPage` ajoute un film, `NavMenu` verra immédiatement le nouveau compteur.

```vue
<!-- NavMenu.component.vue -->
<template>
  <span>{{ count }} film(s) dans ma watchlist</span>
</template>

<script setup lang="ts">
import { storeToRefs } from 'pinia'
import { useWatchlistStore } from '@/store/watchlist'
const { count } = storeToRefs(useWatchlistStore())
</script>
```

```vue
<!-- MovieDetailPage.vue -->
<template>
  <NButton @click="watchlistStore.addMovie(movie)">
    Ajouter à la watchlist
  </NButton>
</template>

<script setup lang="ts">
import { useWatchlistStore } from '@/store/watchlist'
const watchlistStore = useWatchlistStore()
</script>
```

## Persistance de l'état

Par défaut, l'état d'un store est **réinitialisé** si l'utilisateur rafraîchit la page. Pour persister des données (comme le token d'authentification), stockez-les dans le `localStorage` à chaque modification — comme montré dans l'exemple du store d'authentification avec `useStorage`.
