Dans ce chapitre, on continue de construire notre Movie Watchlist en extrayant la logique réutilisable dans des composables : `useMovies()` pour la récupération des films et `useLocalStorage()` pour la persistance.

## Qu'est-ce qu'un composable ?

Un **composable** est une fonction JavaScript/TypeScript qui encapsule et réutilise de la logique réactive. Le terme vient de la **Composition API** de Vue 3.

Un composable se distingue d'une fonction utilitaire classique car il peut :
- Contenir des `ref`, `computed`, `watch`
- Écouter des hooks de cycle de vie (`onMounted`, `onUnmounted`)
- Être partagé entre plusieurs composants sans duplication de code

### Convention de nommage

Par convention, les composables commencent par **`use`** : `useMovies`, `useApi`, `useLocalStorage`, `useAuthStore`, etc.

```
src/
└── composables/
    ├── useApi.ts
    ├── useMovies.ts
    └── useLocalStorage.ts
```

## Exemple : useMovies

Voici comment extraire la logique de récupération des films dans un composable réutilisable. D'abord, la **version inline** (logique directement dans le composant) :

```vue
<!-- HomePage.vue — version sans composable -->
<template>
  <div>
    <p v-if="loading">Chargement...</p>
    <p v-if="error">{{ error }}</p>
    <ul>
      <li v-for="movie in movies" :key="movie.id">{{ movie.title }}</li>
    </ul>
  </div>
</template>

<script setup lang="ts">
import { onMounted, ref } from 'vue'

interface Movie { id: number; title: string; genre: string; year: number; seen: boolean }

const movies = ref<Movie[]>([])
const loading = ref(false)
const error = ref<string | null>(null)

onMounted(async () => {
  loading.value = true
  try {
    const res = await fetch('/api/movies')
    movies.value = await res.json()
  } catch (e) {
    error.value = 'Impossible de charger les films'
  } finally {
    loading.value = false
  }
})
</script>
```

Maintenant, la **version avec composable** — la logique est extraite et réutilisable :

```ts
// src/composables/useMovies.ts
import { onMounted, ref } from 'vue'

interface Movie { id: number; title: string; genre: string; year: number; seen: boolean }

export function useMovies() {
  const movies = ref<Movie[]>([])
  const loading = ref(false)
  const error = ref<string | null>(null)

  const fetchMovies = async () => {
    loading.value = true
    error.value = null
    try {
      const res = await fetch('/api/movies')
      movies.value = await res.json()
    } catch (e) {
      error.value = 'Impossible de charger les films'
    } finally {
      loading.value = false
    }
  }

  onMounted(fetchMovies)

  return { movies, loading, error, fetchMovies }
}
```

```vue
<!-- HomePage.vue — version avec composable -->
<template>
  <div>
    <p v-if="loading">Chargement...</p>
    <p v-if="error">{{ error }}</p>
    <ul>
      <li v-for="movie in movies" :key="movie.id">{{ movie.title }}</li>
    </ul>
  </div>
</template>

<script setup lang="ts">
import { useMovies } from '@/composables/useMovies'

const { movies, loading, error } = useMovies()
</script>
```

> **Avantage :** Plusieurs composants peuvent utiliser `useMovies` — chacun aura son propre état réactif. La logique de fetch n'est écrite qu'une seule fois.

## Composable utilitaire : useLocalStorage

Le composable `useLocalStorage` crée une ref réactive synchronisée avec le `localStorage`. Quand la valeur change, elle est automatiquement persistée.

```ts
// src/composables/useLocalStorage.ts
import { ref, watch } from 'vue'

export function useLocalStorage<T>(key: string, defaultValue: T) {
  const stored = localStorage.getItem(key)
  const initial = stored ? (JSON.parse(stored) as T) : defaultValue

  const value = ref<T>(initial)

  watch(
    value,
    (newValue) => {
      localStorage.setItem(key, JSON.stringify(newValue))
    },
    { deep: true }
  )

  return value
}
```

Utilisation :

```ts
import { useLocalStorage } from '@/composables/useLocalStorage'

// Ref réactive persistée automatiquement
const watchlist = useLocalStorage<Movie[]>('watchlist', [])
const token = useLocalStorage<string | null>('token', null)

// Modifier la valeur met à jour le localStorage automatiquement
watchlist.value.push({ id: 1, title: 'Inception', genre: 'Sci-Fi', year: 2010, seen: false })
```

> **Remarque :** L'option `{ deep: true }` permet de surveiller les modifications en profondeur dans les tableaux et les objets.

## Composable HTTP : useApi

Le composable `useApi` centralise les appels HTTP vers le backend. Il injecte automatiquement le token JWT dans les headers et gère les erreurs de manière uniforme.

### Variables d'environnement avec Vite

Avant de créer le composable, configurez l'URL de base de l'API dans un fichier `.env` :

```sh
# .env
VITE_API_BASE_URL=http://localhost:3001/api
```

> **Important :** Toute variable d'environnement exposée au frontend doit commencer par `VITE_`. Elle est accessible via `import.meta.env.VITE_*`.

### Implémentation de useApi

```ts
// src/composables/useApi.ts
import { useStorage } from './useStorage'

const BASE_URL = import.meta.env.VITE_API_BASE_URL
const storage = useStorage()

const request = async <T>(
  path: string,
  options: RequestInit = {},
): Promise<T> => {
  const token = storage.get<string>('token')

  const headers: Record<string, string> = {
    'Content-Type': 'application/json',
    ...(options.headers as Record<string, string>),
  }

  if (token) {
    headers['Authorization'] = `Bearer ${token}`
  }

  const res = await fetch(`${BASE_URL}${path}`, { ...options, headers })

  if (!res.ok) {
    const data = await res.json().catch(() => ({}))
    throw new Error(
      (data as { message?: string }).message ?? `Erreur ${res.status}`,
    )
  }

  return res.json() as Promise<T>
}

export function useApi() {
  return {
    // Récupérer un film par son id
    getMovie: (id: string) => request<Movie>(`/movies/${id}`),

    // Récupérer la liste des films populaires
    getMovies: () => request<Movie[]>('/movies'),
  }
}
```

Utilisation dans un composant :

```vue
<template>
  <div>
    <ul>
      <li v-for="movie in movies" :key="movie.id">{{ movie.title }}</li>
    </ul>
  </div>
</template>

<script setup lang="ts">
import { onMounted, ref } from 'vue'
import { useApi } from '@/composables/useApi'

interface Movie {
  id: number
  title: string
  genre: string
  year: number
  seen: boolean
}

const api = useApi()
const movies = ref<Movie[]>([])

onMounted(async () => {
  movies.value = await api.getMovies()
})
</script>
```

## Composable vs Store Pinia

Les deux permettent de partager de la logique, mais ont des usages différents :

| Critère | Composable | Store Pinia |
| --- | --- | --- |
| **État** | Local à chaque usage | Global et partagé entre composants |
| **Persistance** | Non (réinitialisé à chaque appel) | Oui (survit aux navigations) |
| **Usage type** | Logique utilitaire, HTTP, localStorage | État d'authentification, panier, données métier |
| **Exemples** | `useMovies`, `useApi`, `useLocalStorage` | `useAuthStore`, `useWatchlistStore` |

> **Règle pratique :** Si plusieurs composants distants ont besoin des **mêmes données** et qu'elles doivent **persister** lors de la navigation, utilisez un store Pinia. Sinon, un composable suffit.
