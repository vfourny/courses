## Qu'est-ce qu'un composable ?

Un **composable** est une fonction JavaScript/TypeScript qui encapsule et réutilise de la logique réactive. Le terme vient de la **Composition API** de Vue 3.

Un composable se distingue d'une fonction utilitaire classique car il peut :
- Contenir des `ref`, `computed`, `watch`
- Écouter des hooks de cycle de vie (`onMounted`, `onUnmounted`)
- Être partagé entre plusieurs composants sans duplication de code

### Convention de nommage

Par convention, les composables commencent par **`use`** : `useCounter`, `useApi`, `useStorage`, `useAuth`, etc.

```
src/
└── composables/
    ├── useApi.ts
    ├── useStorage.ts
    └── useColors.ts
```

## Exemple simple : useCounter

Voici comment extraire la logique d'un compteur dans un composable réutilisable :

```ts
// src/composables/useCounter.ts
import { computed, ref } from 'vue'

export function useCounter(initialValue = 0) {
  const count = ref<number>(initialValue)
  const doubled = computed(() => count.value * 2)

  const increment = () => count.value++
  const reset = () => (count.value = 0)

  return { count, doubled, increment, reset }
}
```

Utilisation dans un composant :

```vue
<template>
  <div>
    <p>Compteur : {{ count }} (double : {{ doubled }})</p>
    <button @click="increment">+</button>
    <button @click="reset">Reset</button>
  </div>
</template>

<script setup lang="ts">
import { useCounter } from '@/composables/useCounter'

const { count, doubled, increment, reset } = useCounter(10)
</script>
```

> **Avantage :** Plusieurs composants peuvent utiliser `useCounter` de façon indépendante — chacun aura son propre état réactif.

## Composable utilitaire : useStorage

Le composable `useStorage` encapsule les opérations sur le `localStorage`, en gérant la sérialisation JSON et les erreurs de parsing.

```ts
// src/composables/useStorage.ts
export function useStorage() {
  const get = <T>(key: string): T | null => {
    const item = localStorage.getItem(key)
    if (!item) return null
    try {
      return JSON.parse(item) as T
    } catch {
      return item as unknown as T
    }
  }

  const set = <T>(key: string, value: T): void => {
    localStorage.setItem(key, JSON.stringify(value))
  }

  const remove = (...keys: string[]): void => {
    keys.forEach((key) => localStorage.removeItem(key))
  }

  return { get, set, remove }
}
```

Utilisation :

```ts
import { useStorage } from '@/composables/useStorage'

const storage = useStorage()

// Stocker un token
storage.set('token', 'eyJ...')

// Récupérer un objet
const user = storage.get<{ id: number; email: string }>('user')

// Supprimer plusieurs clés à la déconnexion
storage.remove('token', 'user')
```

## Composable HTTP : useApi

Le composable `useApi` centralise les appels HTTP vers le backend. Il injecte automatiquement le token JWT dans les headers et gère les erreurs de manière uniforme.

### Variables d'environnement avec Vite

Avant de créer le composable, configurez l'URL de base de l'API dans un fichier `.env` :

```sh
# .env
VITE_API_BASE_URL=http://localhost:3001/api
```

> **Important :** Toute variable d'environnement exposée au frontend doit commencer par `VITE_`. Elle est accessible via `import.meta.env.VITE_*`.

### Implémentation de useApi

```ts
// src/composables/useApi.ts
import { useStorage } from './useStorage'

const BASE_URL = import.meta.env.VITE_API_BASE_URL
const storage = useStorage()

const request = async <T>(
  path: string,
  options: RequestInit = {},
): Promise<T> => {
  const token = storage.get<string>('token')

  const headers: Record<string, string> = {
    'Content-Type': 'application/json',
    ...(options.headers as Record<string, string>),
  }

  if (token) {
    headers['Authorization'] = `Bearer ${token}`
  }

  const res = await fetch(`${BASE_URL}${path}`, { ...options, headers })

  if (!res.ok) {
    const data = await res.json().catch(() => ({}))
    throw new Error(
      (data as { message?: string }).message ?? `Erreur ${res.status}`,
    )
  }

  return res.json() as Promise<T>
}

export function useApi() {
  return {
    // Exemple : récupérer une liste d'utilisateurs
    getUsers: () => request<User[]>('/users'),

    // Exemple : créer un utilisateur
    createUser: (data: { name: string; email: string }) =>
      request<User>('/users', {
        method: 'POST',
        body: JSON.stringify(data),
      }),
  }
}
```

Utilisation dans un composant :

```vue
<template>
  <div>
    <ul>
      <li v-for="user in users" :key="user.id">{{ user.name }}</li>
    </ul>
  </div>
</template>

<script setup lang="ts">
import { onMounted, ref } from 'vue'
import { useApi } from '@/composables/useApi'

interface User {
  id: number
  name: string
}

const api = useApi()
const users = ref<User[]>([])

onMounted(async () => {
  users.value = await api.getUsers()
})
</script>
```

## Composable vs Store Pinia

Les deux permettent de partager de la logique, mais ont des usages différents :

| Critère | Composable | Store Pinia |
| --- | --- | --- |
| **État** | Local à chaque usage | Global et partagé entre composants |
| **Persistance** | Non (réinitialisé à chaque appel) | Oui (survit aux navigations) |
| **Usage type** | Logique utilitaire, HTTP, localStorage | État d'authentification, panier, données métier |
| **Exemples** | `useApi`, `useStorage`, `useColors` | `useAuthStore`, `useCartStore` |

> **Règle pratique :** Si plusieurs composants distants ont besoin des **mêmes données** et qu'elles doivent **persister** lors de la navigation, utilisez un store Pinia. Sinon, un composable suffit.
